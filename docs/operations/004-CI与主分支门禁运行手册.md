# CI 与主分支门禁运行手册

## 1. CI 的责任

CI 是每次代码修改的确定性测试边界，唯一执行定义是 `.github/workflows/ci.yml`。它只回答一个问题：当前提交的后端和前端是否仍满足仓库的代码、类型、业务行为和可构建性契约。

CI 不承担发布演练、外部站点可用性、真实 Provider 会话、AI 账户、浏览器人工验收、完整 Compose 拓扑启停或依赖公告扫描。这些依赖外部状态或低频变更，应在相关变更的本地验证或发布验收中执行，不应阻断每次普通代码修改。

## 2. 必跑边界

| Job | 阻断内容 |
| --- | --- |
| `Backend tests` | Python 依赖锁、Ruff lint/format、strict MyPy、基于 PostgreSQL 17.5 的全量 pytest |
| `Frontend tests` | npm 依赖锁、Biome format/lint、TypeScript、全量 Vitest、Next.js 生产构建 |

两个 Job 并行执行，任意一个失败都会使整个 Workflow 失败，不再设置重复的汇总 Job。同一 PR 或分支的旧运行会被取消。

后端全量测试已覆盖 architecture、contract、integration 和 unit 边界，包括当前 `schema.sql`、Compose 结构、OpenAPI、队列、配额和鉴权契约。前端测试以可观察的业务语义为准，生产构建负责阻断路由、类型和打包回归。

## 3. 本地复现

后端：

```bash
cd backend
uv sync --frozen --dev
uv run --frozen ruff check app tests
uv run --frozen ruff format --check app tests
uv run --frozen mypy app
uv run --frozen pytest -q
```

前端：

```bash
cd frontend
npm ci
npm run format:check
npm run lint
npm test
npm run build
```

涉及 Dockerfile、Compose、容器网络、存储或运行时启动的变更，在提交前额外执行对应 Compose 解析、镜像构建和健康检查。涉及 OpenAPI 的变更，启动当前 API 后执行 `npm run openapi:check`。涉及依赖升级或发布时再执行生产依赖安全审计。

## 4. 失败处理

1. 直接查看 `Backend tests` 或 `Frontend tests` 的第一个失败命令，不再经过汇总 Job 二次定位。
2. 在本地复现同一命令，修复根因后推送新提交；不通过重跑旧提交掩盖不稳定结果。
3. 外部依赖公告、Provider 或宿主环境故障不转换为普通代码 CI 失败；在依赖治理或发布流程中单独处理。

CI 全绿只证明当前提交通过确定性系统测试，不代表真实 Provider、目标部署、备份恢复或人工产品验收已通过。
