# 邮箱验证注册设计

状态：本地实现与验收完成；范围由 2026-09-08 用户确认：邮箱＋密码登录，注册验证邮箱，复用本机 SMTP。

- Web/App 先请求注册验证码，再提交用户名、邮箱、密码与六位验证码。登录仍用邮箱＋密码，成功后沿用各端现有会话。
- 验证码由安全随机数生成，10 分钟有效、60 秒重发间隔、最多 5 次错误；按规范化邮箱绑定，跨端共用。数据库只保存带服务端密钥的摘要，重发使旧码失效，消费原子化；创建账户前验证，创建冲突后可重新请求。
- 发送是独立、有超时的短 HTTP 操作，成功只表示 SMTP 接受。注册请求不发送邮件；本轮不建立通知队列或引入邮件平台。传输失败使该次验证码失效，响应不泄露 SMTP 细节。验证码与凭据不进入日志。
- 复用现有 IP/邮箱限流；SMTP 未配置时发送返回明确不可用，注册不能绕过验证。既有账户的密码登录保留；本轮不宣称已验证其邮箱。
- SMTP 配置采用 SMTP_ENABLED/HOST/PORT/TLS_MODE/USERNAME/PASSWORD/FROM_EMAIL/FROM_NAME；生产 SMTP 必须 TLS，Secret 使用类型化配置，证书验证保持开启。
- 复用现有账户、会话和数据库。Web/App 契约由 OpenAPI 生成；本轮不包含找回密码、邮箱换绑、验证码免密登录或账户注销。

## 接口与部署

- `POST /api/auth/registration-code` / `POST /api/app/v1/auth/registration-code`：`{email}`，返回 `email_sent`、`expires_in_seconds=600`、`retry_after_seconds=60`。
- 两端现有 `register` 请求新增必填 `verification_code`；缺失返回 422，错误/过期/已消费返回 `invalid_verification_code`。邮箱/验证码不匹配不会建立账户。管理员引导仍需原有额外密钥，不绕过邮箱验证。
- `SMTP_TLS_MODE=tls` 使用直连 TLS（常见 465）；`starttls` 使用连接后升级（常见 587），按供应商配置。`none` 仅用于无凭据的本地测试捕获器，生产及带凭据连接禁止明文。SMTP 密码只注入 API，不能注入媒体 Runner 或其他 Worker。
- 发送请求总等待上限 20 秒、每次 Socket 操作 3 秒、每个 API 进程最多 4 个实际发送任务。HTTP 取消/超时后会使验证码失效；底层线程结束前继续占用发送名额，避免超时积累无限在途连接。不会自动重发。
- 数据库 `email_registration_challenges` 每个邮箱一条，记录摘要、过期、次数与发送/消费状态。过期超过一天的记录在后续发送时清理。执行当前态 `backend/sql/schema.sql` 后，API/Web/App 必须同时更新；本轮没有旧无验证码注册分支。
- SMTP 使用 Python 标准库 [smtplib](https://docs.python.org/3.12/library/smtplib.html)，无新增第三方邮件 SDK。邮件正文仅验证码与用途说明，不含密码或业务内容。
