# 031 Linux 无人值守运行计划

- 状态：设计完成，实施未开始；未部署 Linux 服务。
- Design：[设计](../design/031-Linux无人值守运行设计.md)
- PRD：[需求](../prd/031-Linux无人值守运行需求.md)
- Acceptance：[验收](../acceptance/031-Linux无人值守运行验收.md)

| 批次 | 具体交付 | 完成门槛 |
| --- | --- | --- |
| 1. 平台来源验证 | 核实优先平台的服务端授权来源、真实媒体接口、续期能力、出口约束；建立逐平台证据表 | 至少一个现有受控平台完成授权到媒体交付验证；不能以 OAuth 登录或 Cookie 文件存在代替 |
| 2. 凭据生命周期 | 应用层凭据端口、记录绑定密文、独立密钥、版本与撤销语义、管理通道、单 Provider 操作租约；同步 SQL/ORM/契约 | 重建进程可恢复有效凭据；跨账号/版本拒绝；刷新并发和密钥丢失测试通过 |
| 3. Linux 生产入口 | 在现有生产 Compose 中接入已验证来源，移除对应宿主 Chrome 队列挂载，配置系统启动和持久卷 | 无 GUI、无个人浏览器目录、无 macOS 代理时完成冷启动与真实媒体交付 |
| 4. 任务恢复 | 强杀、网络中断、Outbox 重投、lease 回收、旧执行者隔离；根据复现结果修正恢复预算 | 任务不永久卡住；唯一逻辑结果；不存在由重启反复消耗业务重试造成的错误终止 |
| 5. 发布工作流 | 扩展既有 CI 的 Linux 恢复测试，候选镜像平台 canary、灰度与回滚 | 同镜像重启不改配置；候选平台回归被阻止发布；旧任务有明确排空或版本路由 |
| 6. 平台扩展及容量 | 迁移下一平台；落实平台额度、公平调度与资源上限，测量吞吐和延迟 | 按平台及资源配置给出容量实测，之后才推进跨主机 HA |

每批提交独立实现、必要测试与对应验收证据。第 1 批有些平台可能没有可用官方接口，必须记录限制并选择实际可行的授权来源，不能先建一个声称支持全部平台的空 Connector。

目标 Linux 主机、部署 Secret 来源、优先验收平台及有效测试授权尚未提供；不影响仓库内设计与实现准备，但真实授权、部署和冷启动验收必须等待相应环境。当前不修改现有 `.env`、不导出真实 Cookie、不停机迁移、不推送或触发远端发布。
