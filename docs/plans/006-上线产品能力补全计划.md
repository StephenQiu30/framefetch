# 006 上线产品能力补全计划

- 状态：In progress
- 更新：2026-09-10

## 实施与复核

1. 路由显式声明高成本操作限流；已登录业务只按账户计数，管理员豁免，匿名认证叠加客户端 IP。
2. 在持久化事务中统一账户锁、重放判断和可覆盖的账户配额预留；删除全局容量锁，增加并发、覆盖、回滚、窗口、初次分析和删除计量测试。
3. 复用 RabbitMQ `prefetch` 与有界 Worker 池控制各类任务吞吐，保持繁忙任务排队。
4. 用户管理增加账户配额豁免和单项覆盖；同步当前态 SQL、ORM、OpenAPI 与前端生成客户端。
5. 站内任务跳转改为 App Router，认证 Provider 区分首次初始化和后台恢复；Redis Refresh 轮换保留短期冲突标记。
6. 用角色环境白名单替换 Compose 整份 env 注入；同步生产角色校验、可信代理配置和契约测试。
7. 执行后端 lint/format/type/test、前端 lint/format/test/build、SQL 重复执行、业务/生产 Compose 解析、CI 夹具静态解析和浏览器验证。

本机验证复用现有服务和配置，CI 隔离夹具不在本机启动。

## 目标环境待办

- 配置真实 TLS 入口与精确可信代理，检查两名真实客户端的限流隔离和伪造转发头。
- 用有权处理的样本完成下载、两类导入、分析、报告、取消及物理删除的完整容器链路。
- 量测队列、临时上传与工作区峰值、存储、内存、CPU 和 AI 工作量；根据实测调整配额。
- 在隔离恢复环境执行 PostgreSQL 与对象存储备份恢复，检查文件摘要、用户权限、任务状态和可下载性；禁止以恢复操作覆盖生产数据。
- 验证监控告警及值守支持；完善公共账户生命周期与对外政策后再批准开放注册。

验收未完成前不部署公开服务，不把未执行步骤勾选为通过。当前态结构继续使用 `backend/sql/schema.sql`，不引入迁移目录或历史兼容层。
