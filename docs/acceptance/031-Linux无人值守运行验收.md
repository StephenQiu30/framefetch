## 必须提供的运行证据

- [ ] 固定镜像与配置摘要，在无 GUI、无个人 Chrome 和无 macOS 代理的 Linux 环境启动全部已声明能力。
- [ ] 首次授权后连续三次主机冷启动，不人工登录或刷新凭据，已验证平台的有效授权任务均完成。
- [ ] 在下载执行、结果上传、状态提交三个阶段分别强杀并恢复，任务最终收敛且只有一个逻辑成功结果。
- [ ] PostgreSQL、RabbitMQ、对象存储分别中断与恢复；核心就绪状态准确，恢复后任务不永久卡住。
- [ ] 重建容器和清空操作 tmpfs 后可恢复；凭据密文与部署密钥的恢复演练通过。测试不删除真实业务数据。
- [ ] 凭据撤销、自然到期与刷新失败准确隔离；失效后不继续重试受保护操作，重新授权不切换旧任务主体。
- [ ] 多实例同时刷新同一授权时不丢失新令牌；操作日志、错误、制品和共享目录不含凭据明文。
- [ ] 上游解析回归仅影响该平台，候选版本 canary 阻止错误发布，并验证回滚及旧任务处理。
- [ ] 启用的 AI Provider 在同一次无人登录冷启动中可用；未验证的可选能力明确排除出已通过范围。
- [ ] 按平台、样本、镜像版本、授权类型、出口、时间和结果记录证据；未测试与平台要求重新授权不得算作通过。

三次冷启动是最低回归样本，不能推导出长期 SLA。恢复耗时、任务成功率与并发容量要在目标硬件和平台限额下记录基线，再确定可承诺指标。
