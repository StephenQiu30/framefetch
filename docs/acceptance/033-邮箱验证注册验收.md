- Web/App 共用随机六位注册验证码；邮箱绑定、10 分钟有效、60 秒重发、错误次数上限、旧码失效和并发一次性消费通过数据库测试。无验证码请求返回 422，错误验证码不创建账户。
- SMTP 本地协议测试覆盖发送接受、拒收和关闭；失败验证码失效。取消 HTTP 请求不会提前释放实际 SMTP 工作的并发名额。
- 复用本机 Lanverse SMTP 配置，仅补充 Video 缺失的 `.env` / `.env.prod` SMTP 字段，未复制其他配置。实际供应商 TLS、认证和 NOOP 通过；没有发送真实收件人邮件。SMTP_PASSWORD 为 SecretStr，仅注入 API。
- PostgreSQL 当前态 SQL 在已有服务的隔离空 schema、再次执行及现有项目库均通过；隔离检查将 public 加入 search_path 以访问既有 pgcrypto 函数，不另起基础服务。
- 后端 Ruff/Mypy 通过；全量 `pytest`：1652 passed、2 skipped。跳过项是未提供隔离 MinIO 端点的上传测试，以及 macOS 不支持的 Linux O_PATH 测试，均不属于本轮邮件链路。
- Web lint/typecheck/format 通过；57 个文件、232 项测试通过；Next.js production build 通过。
- Flutter analyze/format 通过；175 项测试通过；Android debug APK 与 iOS simulator 构建通过。重新生成 Web/App OpenAPI 客户端；App 冻结契约为 44 个路径、48 个操作，并同步当前服务端已有的音频枚举定义。
- 浏览器实际完成发送验证码、错码提示、验证码注册、退出及邮箱密码再次登录；390×844 和 1280×1000、明暗主题无横向溢出，axe WCAG A/AA 为 0 violations、0 incomplete。验证码、密码、提交及登录交叉入口键盘可达。

## 原生集成与重现

原生集成使用专用 iPhone 17 Pro / iOS 26.5 模拟器、真实生成客户端、PostgreSQL 隔离 schema、Redis 会话及本地 SMTP 协议捕获，不使用固定验证码，也不绕过生产验证码用例。测试环境仅将 IP/邮箱小时限流提高到 100 以允许多次验收；60 秒重发与验证码次数规则保持原值，生产默认 5 次/小时保持不变。

```bash
# 在 backend 中启动，仅监听本机，Ctrl+C 清理隔离 schema 和测试会话
uv run python -m tests.email_registration_server

# 在 video-app 中运行；替换为专用 iOS 模拟器 ID
flutter test integration_test/auth_flow_test.dart -d <simulator-id> \
  --dart-define=VIDEO_SERVER_BASE_URL=http://127.0.0.1:18112 \
  --dart-define=REGISTRATION_TEST_INBOX_URL=http://127.0.0.1:18113/code
```

浏览器可将 Web 的 BACKEND_ORIGIN 指向 18112 后验证相同链路。18113 的测试邮箱读取接口只存在于 `tests/email_registration_server.py`，生产 API 中没有此路由。早期复验失败来自测试库未初始化平台目录及重复运行触发 IP 限流，已修正夹具，未放宽生产约束。
